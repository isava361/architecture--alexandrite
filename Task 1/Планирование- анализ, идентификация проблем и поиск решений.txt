Проблемы и потенциальные риски

1.Потеря или дублирование заказов между MES и CRM через RabbitMQ
Нет явных гарантий идемпотентности, DLQ и мониторинга "застрявших" сообщений. Создание заказа в CRM "по факту сообщения от MES" — хрупкая инверсия ответственности

2. "Узкое горло" и источник задержек
Тяжёлый CPU-процесс (2–30 мин) выполняется внутри MES и синхронно влияет на поток. Нет очереди/воркеров/конкурентности/автоскейлинга

3. Взрыв нагрузки из-за открытого API для продавцов (B2B)
Нет квот, rate limit, backpressure. Возможен DoS тяжёлыми 3D-моделями (много полигонов)

4. Операторская первая страница MES тормозит
Вероятны неэффективные запросы (full scan/сортировки/джойны), пагинация "после сортировки", отсутствие индексов и специализированной read-модели. "Кто успел — тот и получил" создаёт гонки и навигацию по "всем" заказам. Отсутствует кеширование

5. БД используются и для OLTP, и для тяжёлых чтений
Дашборды/фильтры дергают ту же БД, что и транзакции → конкуренция ресурсов, рост латентности

6.Отсутствие сквозной наблюдаемости
Нет трейсинга, алертов на SLA статусов (например, PRICE_CALCULATED > X минут)

7. Хрупкая модель статусов и размытый "владелец состояния"
Разные системы меняют разные статусы. нет явного оркестратора, дедлайнов и эскалаций. Легко застрять между системами

8. Процессы релизов и тестирования не масштабируются
Много ручного E2E, задержки релизов. Нет контрактных/интеграционных/нагрузочных автотестов, нет канареек

9. Справедливость и безопасность "закрепления" заказа оператором
Возможны гонки/двойное взятие/неатомарность, нет "резервации" с TTL

10. Нет "очищающих" и "ревизионных" джобов
Зависшие статусы, незакрытые процессы, невосстановленные ошибки


Инициативы для устранения нежелательных ситуаций

A. Надёжная событийная интеграция (MES/CRM/Shop)
A1. Внедрить идемпотентные потребители для всех публикаций/обработок статусов
A2. DLQ, ретраи с экспоненциальной паузой
A3. Correlation/Idempotency-Key на заказ/внешний запрос, дедупликация.
A4. Мониторинг "мертвых писем", алерты, авто-рекавери.

B. Убрать источник задержек
B1. Вынести из MES API гейтвей
B2. Очередь задач, авто-скейл воркеров по CPU
B3. Внешний API — асинхронный: ввести лимиты на размер/полигоны, лимиты на кол-во обращений
B4. Разделение мощности B2C vs B2B (квоты/приоритеты), протекция от бурстов (token-bucket/Leaky bucket)

C. Починка операторского UX/производительности
C1. Индексы по столбцам сортировки/фильтров, keyset-пагинация (seek) по created_at DESC
C2. Специализированная read-модель (материализованный вид/Redis) для статусов "Новые/Невзятые/Мои"
C3. Кеширование данных таблицы

D. Разделение OLTP/OLAP
D1. Для дашбордов — отдельное чтение (Clickhouse/Elasticsearch)
D2. Убрать "показать всё", пагинировать/сужать период по умолчанию

F. Оркестрация жизненного цикла заказа
F1. Новый сервис - Order Orchestrator с дедлайнами, таймерами и эскалациями
F2. Явный владелец статуса и инварианты (например, CRM владеет "MANUFACTURING_APPROVED/CLOSED", MES — "MANUFACTURING_", Pricing — "PRICE_")

G. Наблюдаемость и качество
G1. OpenTelemetry (трейсы, метрики, логи) сквозь Shop/CRM/MES/Pricing/Queue, дашборды SLO
G2. Алерты: время до PRICE_CALCULATED, застрявшие статусы, глубина очередей, ошибки webhooks
G3. Автотесты: контрактные (Shop, Pricing, CRM, MES), интеграционные, e2e-smoke, нагрузочные
G4. Feature flags, canary

H. Процессы и роли
H1. Автоматизация E2E (QA-инженер + 1 SDET)
H2. Добавить 1 C# backend (вынос Pricing/рефакторинг MES), 1 SRE/DevOps (HA/observability/CI)
H3. Обновить CI/CD: автопромоушн при зелёных канарейках, миграции БД с rollback, "почасовые" хотфиксы через флаги

I. Хаускипинг
I1. Ревизор "зависших" заказов, авто-починка/нотификации
I2. Регламент квот для B2B-клиентов, отчёт по использованию


Инициативы в порядке приоритета

1. Добавить мониторинг, логи и трейсинг в системах
Позволяет определить первопричину проблем и определиться с дальнейшим приоритетом

2. Вынести и асинхронизировать API.
Снимает 2–30-минутный блокер, разгружает MES, вводит управляемый рост и приоритеты B2C.

3. Добавить кеширование, починить отображение на главной странице
Снижает контактность, позволяет быстро починить проблему для покупателей
